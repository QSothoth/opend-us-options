# 评测标准（STANDARD）

实现：`custody/evaluate.py`（常量集中在文件顶部）。本文件与代码必须一致，`custody/tests/test_docs.py` 会检查关键常量。

```bash
python3 -m custody evaluate --dataset <数据集目录> --strategy <id> --out reports/<id>/<dataset>/
```

输出 `report.json`（完整数据）和 `REPORT.md`（中文摘要）。离线、仅标准库、结果确定（同样输入两次运行结果逐字节相同）。

## 1. 要回答的问题

给定上游已经选好的标的、方向和当天到期的合约，**只根据当天正股 1 分钟 K 线决定何时买、何时卖**，争取当天完成一笔、最多一笔；完成率是软目标，不得强制入场。
一个择时策略好不好，看三件事：

1. **方向错了亏多少**：逆势时是否尽早止损；
2. **方向对了拿到多少**：顺势或反转到我方时是否抓住涨幅；
3. 两者合起来的**盈亏比**与**平均每笔收益**，以及这是不是比「不择时」的对照组更好。

## 2. 数据前提

- 数据必须来自真实 OpenD；读取时按 [DATA](DATA.md) 校验真 0DTE、配对行情与校验和，失败直接报错、不产出报告。发布所需的两边要求与遗留数据诊断的区别见下文。
- 每个合约是一个 case，方向由 CALL/PUT 决定；数据集里存的 `direction` 必须与之一致。
- 合成数据永远不能用于评测。
- 每个数据文件都必须由 `CHECKSUMS.sha256` 或 `manifest.json` 的 `series` 逐文件 `sha256` 固定。
- **CALL 和 PUT 必须一起验证**：每个 (标的, 交易日) 都要有同一行权价的 CALL 和 PUT。两边齐全时，当天无论涨跌方向对错各占一半，第 6 节的方向对称加权与简单平均完全一致；两边不全的数据集照常出报告，但结论最高 PROVISIONAL（见第 9 节）。发布前用 `python3 -m custody check` 检查。

## 3. 成交模型（固定，不是可调参数）

对每个 case 按分钟顺序回放：

1. 策略在第 t 分钟**已完成**的正股 K 线上做出决策；
2. 订单在第一根满足「分钟 ≥ t + 1 且成交量 > 0」的期权 1m K 线上成交；
3. 成交价：买入 `min(high, close + 25% × (high − low))`，卖出 `max(low, close − 25% × (high − low))`（即让出该 K 线振幅的 25%，模拟点差和滑点）；
4. 手续费：每张每边 $0.65；
5. 权利金收益率 = `((卖价 − 买价) × 100 − 2 × 0.65) / (买价 × 100)`；美元盈亏同理。

历史数据里没有买卖价，所以这是模拟成交，不是实际可成交的证明。压力测试另外报告：滑点 0%、滑点 50%、延迟 2 分钟。

## 4. 平台规则（与运行时一致）

- 入场必须来自策略 ENTER，平台从不补入场信号。强平时刻及以后禁止新入场决策和买入成交；此前的挂单到点停止等待。
- 出场不得晚于 `flatten_before_close_minutes`（至少收盘前 15 分钟）：到点强制出场（原因 `platform_flatten`）。
- 入场只能在强平时刻之前成交；任何成交都不能晚于收盘。
- 没有入场信号记 `NO_ENTRY_SIGNAL`，有信号但未买入记 `ENTRY_NOT_FILLED`；逐笔收益率为空（没有权利金分母），在全体 case 的经济表现中贡献零，完成分不加分，样本不能删除。
- 买进后如果期权之后再也没有成交（通常是已经接近作废），卖不出去，就按收盘时的内在价值结算（虚值 = 0），只收买入一侧手续费，标记 `settled_at_expiry`，完成情况为 `EXIT_NOT_FILLED`。这笔盈亏保留，但不算完成买入并卖出。策略和对照组同规则。

## 5. 事后场景标签（只用于评测，策略永远看不到）

在开盘到强平这段时间内，令 O = 第一根 K 线开盘价，C = 强平那一分钟收盘价，R = 这段时间最高价 − 最低价，
M = 开盘后第 60 分钟收盘价，s = +1（CALL）或 −1（PUT）：

- 第一小时移动 `m1 = s × (M − O) / R`，其余时间移动 `m2 = s × (C − M) / R`；
- 以 0.25 为阈值把 m1、m2 分级为 +1 / 0 / −1，然后：

| (m1 级, m2 级) | 场景 | 含义 |
|---|---|---|
| (+,+) (0,+) (+,0) | 顺势单边 `trend_with` | 方向对，一路走 |
| (−,+) | 先逆后顺 `reversal_with` | 先反向再回到我方（CALL 的「盘中先跌后涨」） |
| (0,0) | 震荡 `chop` | 没有持续移动 |
| (+,−) | 先顺后逆 `reversal_against` | 先走我方再反转 |
| (−,−) (0,−) (−,0) | 逆势单边 `trend_against` | 方向错，一路反向 |

另外，case 带有 `prev_close`（昨收）时报告「市场形态」交叉表：开盘相对昨收 ≥ +0.2% 为高开、≤ −0.2% 为低开，
全天净移动 ≥ 0.25R 为高走、≤ −0.25R 为低走，例如「低开高走」「高开低走」。V4 没有昨收，显示 `unknown_prev_close`；V5 起由 `custody freeze` 写入。

## 6. 方向对称加权（主口径）

**为什么需要**：数据集里方向对错的比例取决于数据是怎么选出来的（V3 大多是对的，V4 大多是错的）。
不加处理时，「拿得久」的策略在 V3 上看起来好，「砍得快」的策略在 V4 上看起来好——这测的是数据集，不是择时。

**做法**：把场景配成镜像对（顺势单边 ↔ 逆势单边，先逆后顺 ↔ 先顺后逆，震荡自成一类）。
每一对保留它在数据集里的合计频率，但对内两边各占一半（即假设上游方向命中率 50%）；每个 case 的权重 = 所在场景的质量 / 该场景样本数。
某一对只有一边有样本时，这一对从主口径中剔除，并在报告里标为覆盖缺口。

报告同时给出命中率 60% 的加权结果，作为「上游有一定方向能力」时的参考。

## 7. 指标定义

G1 **完成分** = 完成买入并卖出的 case 数 / 全部 case 数 × 100，范围 0–100。空数据集记 0 分。分数单列报告，并按第 10 节占综合分的 20%；不设合格阈值，不因不足 100 分判 INVALID，不得为了加分强制入场。
每个 case 的 `outcome` 为 `COMPLETED`、`NO_ENTRY_SIGNAL`、`ENTRY_NOT_FILLED` 或 `EXIT_NOT_FILLED`；部分成交仍是一笔，离线模型按每张计算。

**方向正确时参与率** = 顺势单边 `trend_with` 与先逆后顺 `reversal_with` 中已买入的 case 数 / 这两类全部 case 数。报告同时列出分子、分母及比例；分母为 0 时记不适用。已买入包括到期结算的 case，所以参与率与要求完成买卖的完成分不同。该指标只用于诊断错过了多少方向正确的机会，不另计分、不设门槛，事后场景标签也不进入策略输入。

同时展示已入场收益指标（含到期结算，未入场不计入），和全体 case 的收益指标。主口径及 G3–G11、压力测试、重抽样均使用**全体 case**：未入场贡献零，成交 / 结算按实际模型计算；不删除未交易 case，不把零贡献当作零收益成交。G12 的两个配对比例例外，以有交易的配对为分母（见下文）。
镜像权重始终基于全部 case 的场景，不按实际参与重新挑样本。单边场景仍记覆盖缺口。盈亏比只比较有盈利 / 亏损的交易，缺任一侧记不适用；零交易不能 ACCEPT。

在加权后的 case 集合上（`n` 为有效 case 数）：

| 指标 | 定义 |
|---|---|
| 每个 case 平均收益（期望） | 各 case 收益贡献的加权平均（已买入按权利金收益率；未入场贡献零） |
| 盈利 case 占比 | 收益贡献 > 0 的权重占比（分母包括未入场 case） |
| 平均盈利 / 平均亏损 | 盈利单（亏损单）收益率的加权平均（亏损取绝对值） |
| **盈亏比** | 平均盈利 / 平均亏损 |
| 利润因子 | 加权总盈利 / 加权总亏损 |
| 上涨捕获 | 只统计「入场后最佳可卖出收益 ≥ +20%」的 case：`clamp(实际收益 / 最佳收益, 0, 1)` 的平均 |
| 美元口径 | 同样的定义用每张合约的美元盈亏计算，作为辅助 |

**同一标的 CALL 和 PUT 合起来看（配对，G12）**：同一标的、同一天、同一行权价的 CALL 和 PUT 算一对，只统计两边都在数据集里的配对。
买入的每一边按 1 张合约计，配对盈亏 = 两边美元盈亏之和（含手续费、到期结算），配对收益率 = 配对盈亏 ÷ 实际付出的权利金；
两边都没买的配对没有仓位，不算赚也不算亏。有交易的配对 = 至少买了一边的配对，下列比例除特别注明外都以它为分母。
方向对称加权的平均值已经把每一对平均进去了，但看不出分布，所以报告另给：合起来赚钱的配对比例（另给占全部配对的比例）、
合起来亏钱的比例、亏掉超过一半（50%）权利金的比例、有交易配对的收益中位数和最差一对、每对平均美元盈亏（没买记 0），
并按「两边都买 / 只买了方向对的一边 / 只买了方向错的一边 / 只买了一边（震荡日）/ 两边都没买」拆开（对错按买入那一边的事后场景）。
对照组两边都在 09:35 买入、拿到 15:45，相当于开盘买入跨式。它回答的是「上游方向判断错了的那一边，能不能被对的一边盖住」；
G12 用其中两个比例判定（第 9 节），不进综合分，有样本外交易日时另给样本外的配对结果。

## 8. 对照组与可靠性检查

- **对照组：09:35 买入，拿到 15:45 卖出**。同一张合约、同样的成交规则和手续费，开盘后第 5 分钟就买，一直拿到强平。它代表「完全不择时」。策略的意义就是要比它好：平均收益更高、方向错时亏得更少。它只是一把参照尺，不是可注册的策略。
- **打乱时点对照**：把策略自己的（入场分钟、出场分钟）组合在 case 之间随机重新分配 1000 次，连同未入场的空时点一起打乱，保持参与数量与时点分布不变，只打断「这一天的走势 ↔ 选中的时点」之间的联系。p 值 = 打乱后平均每笔收益（或盈亏比）≥ 策略本身的比例。p 小说明择时确实用上了当天的走势。
- **前缀一致性（G2）**：把每个 case 截断到策略的入场 / 出场决策分钟再回放一次，决策必须完全相同。未入场 case 也在每个整小时截断检查。用来发现偷看未来、依赖随机数或跨实例状态的实现。

### 防过拟合检查（G8–G10）

数据少的时候，一个策略可能只是碰巧在某几天、某一组参数上好看。以下三项专门抓这种情况，任何一项不过都是 REJECT：

- **前后两半（G8）**：把交易日按时间分成前一半和后一半，在每一半里，对同一批合约比较策略和对照组的简单平均收益（两者方向构成完全相同，不需要加权），两半都必须是策略更好。
- **去掉任意一天（G9）**：每次去掉一个交易日的全部合约，重新按方向对错各半计算；每一次都要求策略的平均收益和盈亏比同时高于对照组。
- **按交易日重抽样（只报告，不作门槛）**：把交易日有放回地重抽 1000 次，给出方向对称平均收益、盈亏比、以及「策略减对照组」的 95% 区间。区间跨过 0 表示还不能确定比对照组好。
- **参数邻域（G10）**：策略参数文件里每个非零数值参数分别乘以 0.75 和 1.25（整数至少变动 1，引擎判为无效的组合跳过），每一组都要求平均收益和盈亏比同时高于原对照组。只在某个精确参数值上成立的效果不算数。

## 9. 门槛与结论

| 门槛 | 要求 |
|---|---|
| G1（单列分数） | 完成买卖 case 数 / 全部 case 数 × 100，占综合分 20%，不参与硬门槛判定 |
| G2 | 前缀一致性通过 |
| G3 | 方向对称加权的平均每笔收益 > 对照组，按收益率和按美元（每张合约）都要成立 |
| G4 | 方向对称加权的盈亏比 ≥ 2 |
| G5 | 逆势单边场景的平均收益 > 对照组（方向错时亏得更少） |
| G6 | 方向正确的场景（顺势单边 + 先逆后顺）平均收益 > 0 |
| G7 | 方向对称加权的盈亏比 > 对照组，按收益率和按美元都要成立 |
| G8 | 前后两半交易日都赢对照组 |
| G9 | 去掉任意一个交易日，平均收益和盈亏比仍都赢对照组 |
| G10 | 每个参数上下浮动 25%，平均收益和盈亏比仍都赢对照组 |
| G11 | 方向对称加权的利润因子（总赚 ÷ 总亏）> 1，即整体赚钱 |
| G12 | 同一标的 CALL 和 PUT 配对（有交易的配对）：合起来赚钱的比例 > 对照组，且亏掉超过一半权利金的比例不超过 10% |

为什么 G4 之外还要 G7 和 G11：买期权天生「亏有底、赚无顶」，完全不择时的对照组按收益率算盈亏比就有 2.3 左右，
所以「盈亏比 ≥ 2」几乎没有鉴别力；按美元算（固定每次 1 张）对照组只有 1 左右。策略必须在两种口径下都赢对照组，并且整体赚钱。

为什么要 G12：上游方向大体有判断，同一标的的 CALL 和 PUT 成对入库是为了检验容错。平均值把每一对平均在一起，看不出同一标的上错的一边有没有被对的一边盖住。
G12 不要求每一对都赚钱（做不到），只要求两件事：赚钱配对的比例高于完全不择时的开盘跨式（与 G3、G5、G7 一样以对照组为锚），
以及亏掉一半以上权利金的配对最多十对里一对（「大概率不会亏太多」）。分母只算真正持有仓位的配对，参与不足由完成分体现。
两个数值是在看过已注册策略和 R12 / R13 候选的配对分布后设定的：训练集 V5 上对照组赚钱配对 25.4%、亏掉一半以上 39.7%；
v6.1 / v6.2 / v6.3 赚钱配对 22.2% / 23.9% / 20.5%，亏掉一半以上 3.2% / 2.2% / 0%；R12 / R13 的 10 个候选中 7 个赚钱配对比例高于对照组，亏掉一半以上都不超过 8.7%。

另有三个证据充分性条件：**CALL/PUT 两边齐全**（每个标的每天同一行权价的两边都在）、**场景覆盖**（5 类场景每类 ≥ 5 个 case）和**样本外交易日 ≥ 20**。

| 结论 | 条件 |
|---|---|
| INVALID | G2 未通过 |
| REJECT | G3–G12 有任一未通过 |
| PROVISIONAL | 没有未通过的门槛，但有门槛「不适用」、数据集 CALL/PUT 两边不全、场景覆盖不足或样本外交易日 < 20 |
| ACCEPT | 门槛全部通过、两边齐全、场景覆盖满足，且在 ≥ 20 个样本外交易日上门槛仍全部通过 |

- 样本外 = 交易日晚于策略 `developed_on.sessions_through` 的 case。样本外交易日 ≥ 20 时，G3–G12 以样本外结果判定，完成分同时报告全样本与样本外；否则以全样本判定，结论最高 PROVISIONAL。
- 只有 ACCEPT 的策略可以把状态改成 `accepted`，也只有 `accepted` 可以进入 live。
- **不适用**：门槛需要的指标在这份数据上算不出来时记「不适用」，而不是「未通过」。例如镜像对只有一边有样本（方向对错各半算不出，影响 G3、G4、G7、G10、G11）、某类走势没有样本（G5、G6）、交易日少于 2 个（G8、G9）、没有两边齐全的配对或没有任何有交易的配对（G12）。有「不适用」的结论最高是 PROVISIONAL。随机时点对照和按交易日重抽样在同样情况下报告「无法计算」。
- **同批直接对比**：报告总是另外给出「同一批合约、不加权」的策略与对照组对比。两者评测的 case 集合完全相同（实际参与可以不同）、方向构成一样，所以这张表本身是公平的；只是绝对数值受数据集方向对错比例影响。方向对错各半算不出来时，以这张表为准。
- 对照组未入场的 case 同样贡献零；买入后无法退出的按到期内在价值结算，统一保留在总体指标中。

## 9b. 不择时执行策略的判定（`open_hold` 引擎，2026-09-20 起）

[custody/AGENTS](../custody/AGENTS.md#边界) 在 2026-09-20 由用户决定增设第二类策略：在开盘后固定分钟买入、持有到平台强制平仓，中间不做任何决策。它**就是本标准的对照组**，因此第 9 节里所有「优于对照组」的门槛（G3、G5、G7、G8、G9、G10、G12）对它没有意义，报告照常计算并展示，但不以它们判定结论。

这类策略按下列口径判定，只用方向对称加权之外的原始场景均值（不假设命中率）：

| 项目 | 定义 |
|---|---|
| 方向对时收益 | 顺势单边 + 先逆后顺的平均每 case 收益 |
| 方向错时收益 | 逆势单边 + 先顺后逆的平均每 case 收益 |
| 震荡时收益 | 震荡场景的平均每 case 收益 |
| **盈亏平衡命中率** | 使「震荡占比 × 震荡收益 +（1 − 震荡占比）×（p × 方向对 +（1 − p）× 方向错）= 0」成立的 p |

**判定量（2026-09-20 修订，原因见下）**：盈亏平衡命中率单独使用是不够的，它只回答「命中率高于多少才开始赚钱」，完全不反映「赚多少」。因此这类策略按两项判定，两项都要报告：

1. **盈亏平衡命中率**，必须 < 100%（否则任何命中率下都不赚钱）；
2. **参考命中率下的每笔期望收益**：取 75% 和 85% 两点（覆盖产品当前估计的上游命中率区间两侧），两点的期望收益都要比被比较的对象更高，才算更优。

比较两个同类策略时，先看第 1 项是否满足，再按第 2 项排序；只有一点更好、另一点更差时，判为无结论，不得声称更优。

**结论**：这类策略的结论**最高只能是 PROVISIONAL**，并且必须与上游方向命中率的独立估计一起使用；在该估计存在且可信之前，不得 ACCEPT，也不得用于 `--mode live`。

盈亏平衡命中率低不等于更好：它与单笔风险、与盈利幅度都无关。报告同时展示方向错时的平均亏损与最差一笔，用于仓位管理判断（择时策略与它在这一项上差别很大）。

## 10. 综合分（比较版本用）

门槛决定结论（第 9 节）。比较两个版本、或在一轮研究里挑候选时，单看门槛和某一个指标常常说不清谁更好（例如盈亏比升了、利润因子降了），所以把关注的指标合成一个 0–100 的综合分。**综合分 = 80% × 收益分 + 20% × 完成分**。收益分保留原有四项收益指标的计算方式，完成分按第 7 节计算。**综合分不改变结论**：REJECT 的策略综合分再高也不能上线。

| 收益分项目 | 刻度（0 分 → 0.5 分 → 1 分） | 收益分内部权重 | 原始指标 |
|---|---|---:|---|
| 盈亏比（主指标） | 1 → 2 → 4（对数刻度） | 2 | 方向对称盈亏比 |
| 整体赚钱：总赚 ÷ 总亏 | 0.5 → 1 → 2（对数刻度） | 1 | 方向对称利润因子 |
| 方向对时拿住：顺势单边 + 先逆后顺平均 | 0 → +50% → +100% | 1 | 这两类走势的每 case 平均收益（未入场记 0） |
| 方向不利时少亏：逆势单边 + 先顺后逆 + 震荡平均 | −100% → −50% → 0 | 1 | 这三类走势的每 case 平均收益（未入场记 0） |

收益分 = 上表各项得分按内部权重平均 × 100。四项齐全时，它们分别占最终综合分的 32%、16%、16%、16%，完成分占 20%。例如收益分为 80、完成分为 40，综合分为 72。

主口径假设上游命中率 50%。报告另给上游命中率 60% 的综合分：盈亏比和利润因子改用第 6 节命中率 60% 的加权（镜像对内按 60 : 40，震荡保持原频率）；「方向对时拿住」「方向不利时少亏」是按走势分组的平均，数值和内部权重都不变。两种命中率下均按同一批原始 case 的完成买卖数 / 总 case 数计算完成分，不按方向重新加权；外层 80% / 20% 权重也不变。

收益分刻度两端以外截断为 0 或 1；从没赚过一笔时，盈亏比和利润因子两项记 0 分，没有亏损单时记 1 分。数据算不出的收益项目（例如没有方向对的 case）不计入，只在收益分内部重新归一权重，完成分仍占最终综合分的固定 20%。如果收益分无法计算，综合分也记不适用，不单凭完成分产生综合分。

为什么这样算：

1. **刻度固定，锚点取自门槛**：盈亏比 2（G4）和利润因子 1（G11）落在 0.5 分，方向对时平均 0（G6）是 0 分。不用候选之间的最高、最低值归一化，否则每多一个候选所有分数都会变，不同轮次也没法比。
2. **比值用对数刻度**：盈亏比从 1 到 2 与从 2 到 4 各算 0.5 分，翻倍的难度相同。
3. **收益分内部等权、主指标加倍**：把各项换算到同一刻度后简单等权相加（Dawes 1979 的「不当线性模型」），通常和拟合出来的权重一样好，也避免在训练集上把权重调成对某个候选有利；盈亏比是主指标，在收益分内部占 2 份。外层 80% / 20% 是预先固定的产品偏好，不根据候选结果拟合。
4. **同时衡量收益和完成交易**：未入场的 case 在两项平均收益里记 0，在盈亏比和利润因子里既不算赚也不算亏。另用 20% 完成分体现参与不足的代价，避免只改善已交易子集的盈亏比就掩盖大量未交易 case。方向覆盖齐全时，全天不交易的策略收益分为 20、完成分为 0，综合分为 16 分。完成率仍是软目标，没有信号可以不交易；完成分不能覆盖收益门槛的失败。方向正确时参与率另列用于诊断，不重复计分。上游命中率 60% 的检查继续保留，用来检验上游方向更准时的表现。
5. **稳健性不重复计分**：前后两半、去掉任意一天、参数浮动和美元口径仍由 G3、G7–G10 把关，不进综合分。报告给出按交易日重抽样的综合分 95% 区间（重抽样做法见第 8 节）；每次重抽样都按抽中的 case 重新计算收益分和完成分，再按 80% / 20% 合成。两个版本的差距小于区间宽度时，不能说谁更好。

用法：

- 报告同时给出对照组的综合分作参照；有样本外交易日时另给样本外综合分，收益分、完成分均只按对应样本计算。
- 研究轮次挑候选：先比未通过门槛数（「不适用」按未通过计），再比综合分，高者优。判定新版本优于基线，还要求上游命中率 60% 时的综合分也高于基线。交易太少的候选会在 G4、G7、G9–G11 上「不适用」或未通过，先比门槛数就能把它排在后面。
- 刻度和权重是本标准的一部分，按第 13 节的规则修改。

## 11. 怎么读报告

1. 先看结论和门槛表：INVALID 说明实现有问题；REJECT 说明策略本身不达标；PROVISIONAL 说明还缺证据。
2. 再看综合分和总体表，和对照组比平均每笔收益、盈亏比、平均亏损、完成分及方向正确时参与率。
3. 分场景表看适配性：逆势单边、震荡要亏得少；顺势单边、先逆后顺要赚到。
4. 同一标的 CALL 和 PUT 合起来看（G12）：合起来赚钱的配对占多少、亏掉一半以上的有多少，两边都买的配对是不是在两头挨打。
5. 结果靠不靠得住：随机时点 p 值、前后两半、去掉任意一天、参数浮动、成交压力下是否翻转。
6. 逐笔表用来定位问题，不用来挑数据。

## 13. 修改本标准的规则

- 标准的任何修改（成交模型、标签阈值、权重、门槛）必须同时改 `custody/evaluate.py`、本文件和测试，并在同一次改动里重跑所有已注册策略的报告。
- 不允许为了让某个策略通过而改标准；门槛只能因产品要求变化而调整，并写明原因。
