# OpenD 能给什么：港股全市场实测（2026-09-22，账号 LV1）

全部结论来自本机 OpenD（`127.0.0.1:11111`，`futu-api` 10.11.7108）的实际调用，不是文档推断。
只用 `OpenQuoteContext`，没有碰交易接口。

## 1. 三种额度是三回事

| 额度 | 上限 | 当前 | 谁在消耗 | 本项目影响 |
|---|---|---|---|---|
| 历史 K 线 | 300 只 / 30 天 | 已用 188，剩 **112** | `request_history_kline`，每只股票 30 天内只扣一次 | **美股 0DTE 每日 `freeze` 靠它，过期周权补不回来。港股回测不得挪用** |
| 订阅 | 300 | 已用 0 | `subscribe`（K 线 / 摆盘 / 逐笔 / 分时） | 全市场 662 只**装不下**，只能给短名单用 |
| 快照 / 选股 | 只有频率限制 | — | `get_market_snapshot`、`get_stock_filter`、`get_capital_flow` | **不扣额度，全市场可用** |

实测：`get_history_kl_quota(get_detail=True)` 给出已扣费清单，其中 **164 只港股**（与港股通交集
**140 只**）在 2026-10-20 前重复拉取免费。本轮回测就建在这 140 只上，剩余 112 额度一分没动。

## 2. 全市场能力（不扣额度）

| 接口 | 实测 | 用途 |
|---|---|---|
| `get_plate_stock('HK.GangGuTong')` / `('HK.LIST1922')` | 0.2s，并集 693 条、正股 **662 只** | 港股通名单，无需自己维护 |
| `get_market_snapshot(400 codes)` | **0.7s / 批**，662 只 = 2 批 ≈ 1.5s | 全市场扫描的唯一可行入口 |
| `get_stock_filter(market=HK, plate_code=...)` | 0.4s，分页 200，`all_count=640` | 服务端粗筛（涨跌幅 / 量比 / 换手 / 均线 / RSI / MACD / KDJ / 形态） |
| `get_capital_flow(period_type=INTRADAY)` | 0.09s / 只，662 只 ≈ 60s | 分钟级主力 / 超大 / 大 / 中 / 小单净流入 |
| `get_capital_distribution` | 同上 | 当日累计四档买卖额 |

快照里对量价形态直接有用的字段（无需订阅）：
`last_price`、`open_price`、`high/low_price`、`prev_close_price`、`volume`、`turnover`、
`volume_ratio`（量比）、`turnover_rate`（换手率）、`amplitude`（振幅）、
`bid/ask_price`、`bid/ask_vol`、`bid_ask_ratio`、`circular_market_val`、`price_spread`、
以及 **`avg_price`**。

`avg_price` 实测恰好等于 `turnover / volume`（HK.00001：310894666 / 4601495 = 67.5638 = `avg_price`），
**就是当日 VWAP**。也就是说盯盘脚本的核心偏向输入（价 vs VWAP）对全市场 662 只是免费且即时可得的，
不需要任何订阅。**注意这些字段在持续交易时段成立，竞价时段另见第 3b 节。**

## 3. 需要订阅的（300 只上限，只给短名单）

| 接口 | LV1 下的实测结果 |
|---|---|
| `get_cur_kline(code, 1000, K_1M)` | 可用，**1000 根 ≈ 3 个交易日**，不扣历史额度 |
| `get_order_book` | 可用，但 **LV1 只给 1 档**（`Bid: [(430.0, 43700, 8)]`），没有 10 档深度 |
| `get_rt_ticker` | 可用（逐笔，含 `ticker_direction`） |
| `get_rt_data` | 可用（分时 331 行，含逐分钟 `avg_price`） |
| `get_broker_queue` | **不可用**：`在 LV1 权限下，不支持获取经纪队列` |

三条实测到的坑（都写进了 `code/baseline.py`）：

1. `subscribe` 只要列表里有一个不支持的 SubType，**整次订阅失败返回 −1**，其余类型也不会生效。
2. **订阅额度不由 `unsubscribe` 释放，关闭连接也不释放**：两者都做完之后
   `query_subscription` 仍报 `5/295`，释放走 OpenD 自己的计时器。
   所以 662 只**一次跑不完**，只能每次取 300 只、按最久未更新轮换，几个交易日覆盖一遍。
3. **订阅后立刻调 `get_cur_kline` 拿到的是残缺帧**：实测第一只只回 60 根（应为 1000 根），
   等 3 秒后正常。

## 3b. 竞价时段的字段语义（2026-09-22 实测，覆盖 09:00 起的输入期）

港股开盘竞价（POS）分四段：**09:00–09:15 输入期**（可下、可改、可撤）、
**09:15–09:20 不可撤销期**（只能下单）、**09:20–09:22 对盘期**（这两分钟才产生成交）、
**09:22–09:30 暂停期**，09:30 开始持续交易。**09:20 之前没有任何成交**，
交易所只按挂单簿广播 IEP（参考平衡价）和 IEV（参考成交量）。

实测快照在 09:00–09:20 的表现：

| 字段 | 实测 | 能不能用 |
|---|---|---|
| `prev_close_price` | 09:00 前后即滚到昨收 | **能**，竞价中可实时算跳空 |
| `bid_price` / `ask_price` | 有交叉时两者相等，就是当下的 IEP；无交叉时分开 | **能**，但必须先判 `bid_price == ask_price` |
| `bid_vol` / `ask_vol` | 随挂单逐轮变动，两侧接近但不相等 | **能**，竞价段唯一的参与度来源 |
| `last_price` | 有交叉时等于 IEP；无交叉时退回昨收，**无信息** | 有条件 |
| `volume` | 140 只里 **99 只恒为 0**，其余是 485 / 385 / 594 这类几百股的非整手碎数，且从 09:01 起**冻结不动**；与昨日收盘竞价量、开盘竞价量、全日量**均不匹配** | **不能**。既不是成交量（09:20 前不可能有），也不是 IEV（IEV 会随簿子变）。来源未确认，不作为因子 |
| `volume_ratio`（量比） | 竞价全程 **恒为 0** | **不能** |
| `turnover` | 与 `volume` 同源 | 不能 |

举例（HK.00700，09:00–09:04 每轮快照）：`last_price` 走 433.2 → 454.8 → 459.8 → 450.0，
`bid_vol` 走 257,400 → 632,000 → 794,300 → 657,000，而 `volume` 自 09:01 起固定在 313,126 不动。
价和簿都在动、`volume` 冻结，说明它既不是撮合结果也不是随簿子推算的 IEV。

### 撮合前后的对账（全市场 480 只，2026-09-22）

| 时刻 | `volume>0` 的只数 | 盘口交叉（有 IEP）的只数 | 中位 \|失衡\| | 中位 `bid_vol` |
|---|---|---|---|---|
| 09:05 | 77 | 357 | 0.200 | 12,000 |
| 09:14 | 77 | 410 | 0.200 | 12,000 |
| 09:19 | 77 | 443 | 0.167 | 15,300 |
| 09:21（撮合后） | **480** | 0 | — | — |
| 09:31 | 587 | 0 | — | — |

`volume>0` 的只数从 09:05 到 09:19 **一直是 77，纹丝不动**，撮合后一次跳到 480；
说明那 77 只的 `volume` 是与竞价无关的另一路数据。撮合完成后盘口不再交叉，恢复正常买卖价。

**09:19 的挂单量 vs 撮合后的实际成交量（n = 480）：**

| 比值 | 中位 | p10 | p90 |
|---|---|---|---|
| 成交量 / `bid_vol` | 1.15 | 0.33 | 3.10 |
| 成交量 / `ask_vol` | 1.14 | 0.54 | 3.00 |
| 成交量 / `min(bid_vol, ask_vol)` | **1.32** | **1.00** | 4.02 |

`min(bid_vol, ask_vol)` 的 p10 恰好是 1.00，且 **130 / 480（27%）精确相等**——
实际撮合量**从不低于**它。所以 `min(bid_vol, ask_vol)` 就是当前 IEP 下的可撮合量，
**是最终成交量的下界**，这才是 IEV 的正确取法。差出来的 1.32 倍来自 09:19–09:20
不可撤销期里继续涌入的单子和竞价市价盘。

结论：**竞价窗口唯一可用的参与度信号是盘口挂单量（`min(bid_vol, ask_vol)` 与失衡），
不是 `volume`**。相对量必须靠本目录 `baseline.py` 自己滚动的历史基准，
不能指望快照里的现成字段。

（需要留意的是，R2 已经证明**即使精确已知撮合结果**也过不了门槛，所以「有了正确的 IEV」
并不能救活窗口一——管子是通的，信号在这批大盘股上不存在。）

## 4. 竞价窗口：历史上根本不存在

港股 1 分钟历史 K 线**第一根是 09:30、最后一根是 16:00，每天 331 根**。实测 140 只 × 21 天：

- **09:30 那根就是开盘竞价成交本身**——2939 / 2940 个标的-日是 O=H=L=C 的十字，价格等于日线
  `open`，量等于 09:20–09:22 撮合出来的量。连续交易实际从 09:31 开始。
- 16:00 那根是收盘竞价（`smc_watch.py` 已经把它剔掉了）。
- 09:00–09:22 没有任何 K 线。

因此：

| 东西 | 有没有历史 | 能不能回测 |
|---|---|---|
| 竞价**结果**（撮合价、撮合量） | 有（09:30 那根） | **能** |
| 竞价**过程**（IEP 路径、挂单失衡） | 无 | **不能，只能逐日前瞻采集** |
| 开盘后 15 分钟 1m 量价 | 有 | **能** |
| 分钟级资金流 | 无（`INTRADAY` 只返回最近一个交易日，传 `start`/`end` 被忽略） | **不能，只能前瞻采集** |
| 日级资金流 | 有（`PeriodType.DAY` 可取区间） | 能，但粒度不够开盘窗口用 |

这就是为什么 `capture.py` 必须每个交易日实时跑一次：那 22 分钟的数据错过就永远没有了。

## 5. 成本：tick 才是真门槛

港股通 400 只的快照实测 `price_spread / last_price`：

| 分位 | 一个 tick | 例子 |
|---|---|---|
| p5 | 5.1 bp | 中国心连心化肥 9.895 / 0.005 |
| p50 | **8.3 bp** | 东岳集团 12.00 / 0.01 |
| p75 | 12.8 bp | 中国软件国际 3.91 / 0.005 |
| p95 | 43.7 bp | 香港中旅 1.145 / 0.005 |
| p100 | 120.5 bp | 喜相逢集团 0.415 / 0.005 |

`watch/README.md` 里的「成本门槛约 0.10%/笔」在中位数上成立，但 **30.5% 的港股通标的一个 tick
就超过 10 bp，14.2% 超过 20 bp**。横截面选股如果不先按 tick 过滤，「量价形态最强」会系统性选出
便宜的小票，而那里的形态很大程度上是 tick 跳动本身。

另：实测 tick 档位比经典 HKEX 价差表窄一半（49.4 元报 0.02 而非 0.05，12.0 元报 0.01 而非 0.02），
**不要硬编码档位表，直接读快照的 `price_spread`**。
